## Session 2 — shell unification (design rebuild, user request #2)

User: "rebuild the design from the ground up … feel native like a real app … netflix
style / apple design". Plan chosen: **Option 1 — unify the shell**, with the detail pane
folded in.

### Build unblocker
`HttpStatusCode.PermanentRedirect` (308) does not exist on net481. Replaced with a
`private const int PermanentRedirect = 308;` and a numeric comparison. Both targets now
build clean with:
`dotnet build GUI/CKAN-GUI.csproj -f <tfm> -c Debug --no-restore`

### SpaceDock artwork — root cause CORRECTED
The earlier note blaming `SpaceDockId` was a **misdiagnosis**. Verified:
- Scatterer's real SpaceDock mod id is **141**; the `378` in its banner URL is
  *blackrack's author id*, a different namespace. `SpaceDockId` extraction was fine.
- `https://spacedock.info/api/mod/141` -> `background` is an **absolute URL**.
  The old code prefixed `https://spacedock.info/` again -> `.../https://spacedock.info/...`
  -> 404. `SpaceDockBannerUrl` now accepts absolute URLs and only prefixes relative ones.

### Stale cache made the fix invisible (new finding)
The art cache stores the **already-resolved** `bannerUrl`, and the cover image was keyed
by `{identifier}.cover.bin` only. So a resolver fix could never reach an existing cache.
Fixed by:
- `CacheFormatVersion = 2` written as `"v"` in `.info.json`; entries below it are treated
  as stale and re-resolved (`JsonInt` helper added).
- Cover file renamed to `{identifier}.{fnv1a(bannerUrl)}.cover.bin` (`CoverKey` +
  `StableHash`), so a changed source is a cache miss. Legacy `{id}.cover.bin` is deleted
  once a replacement is written.
Verified end-to-end: the three Scatterer cards went from generated gradient fallbacks to
the real SpaceDock banner, and cache entries now read `v=2` with clean URLs.

### `ThemedTabControl` rewritten (outer tabs + detail pane tabs)
Was: OS visual style in dark mode, bare text on a rectangle in light mode.
Now: fully owner-painted (`ControlStyles.UserPaint`), flat band on `Backdrop`, hairline
under the strip, **accent underline** on the active tab, hover on the others, uniform
`ItemSize` for a segmented-control feel, `Multiline = true` so overflow wraps instead of
hiding behind scroll arrows (this is the fix for the Changelog tab being unreachable).
- `RefreshTabMetrics()` recomputes `ItemSize` on handle-create / DPI change / page added /
  selection change, because tab text arrives from resx after construction.
- **Important gotcha:** `TabDrawMode.OwnerDrawFixed` is NOT enough. The native control
  still paints the band and page frame, and it repaints only the *invalidated* region, so
  a strip-wide background pass from `OnDrawItem` erased the other tabs' labels whenever a
  single tab was invalidated (only "Metadata" rendered). Owning the whole paint fixed it.
- `SoftTheme.TabFont` / `TabFontActive` added (9.5pt regular / bold).
- `Main.ApplySoftChrome` now themes `splitContainer1`, `MainTabControl`, and every
  `TabPage` (via a `ControlAdded` hook, since `TabController` adds/removes pages).

### Detail pane
`ModInfo.ApplySoftTheme()` + `Metadata.ApplySoftTheme()` added. Colours only — the
designer fonts are left alone because `ScaleFonts()` has already applied the user's text
scale factor. `Metadata` walks its tree mapping `SystemColors.Control` -> transparent,
`ControlText` -> `TextPrimary`, `GrayText` -> `TextMuted`, and links -> `Accent`.

### Tab sizing — WinForms gotchas found the hard way
Iterated three times on `ThemedTabControl` sizing; the findings are non-obvious:
1. `TabSizeMode.Fixed` + `ItemSize.Width` = uniform tabs sized to the **longest** label.
   The detail pane's five labels need ~478 px of text but the longest ("Relationships")
   forces ~162 px per tab, so 5 tabs = 810 px and they wrap to two rows in a ~694 px pane.
2. Assigning `ItemSize` at all overrides auto-sizing: with `ItemSize.Width = 90` the tab
   for "Manage Mods" (~105 px of text) was **ellipsized to "Manage Mo..."**. So in
   `Normal` mode, do **not** assign `ItemSize` — let the native derive width from the label.
3. Setting `TabPage.Font` (to get a bold selected tab, since the native sizes tabs from the
   *page* font) makes the page's **whole content inherit the bold**. The Metadata tab turned
   bold. Not worth it: the strip uses one weight and signals selection with `TextPrimary`
   plus the accent underline instead.
Result: `TabSizeMode.Normal`, no `ItemSize` assignment, `Multiline = true` as the overflow
fallback, single weight. `DesignStripHeight` / `DesignMinTabWidth` / `SoftTheme.TabFontActive`
were removed as dead.

*(Correction to the entry above: "uniform `ItemSize` for a segmented-control feel" and
"`SoftTheme.TabFont` / `TabFontActive` added" describe an intermediate state that was
superseded by the final `Normal`-mode, single-weight design.)*

### Collapsible shelf (`ModCarouselRow`)
`collapseButton` (`▾` expanded / `▸` folded, `\u25BE` / `\u25B8`) sits left of the title; the
title label toggles too so the hit target is the whole heading. `SetCollapsed(value, notify)`,

**The folded state lives on `ModDiscoverView.collapsedSections` (a `HashSet<string>` of section

row-owned flag would spring every shelf back open.
Verified round-trip: shelf titles `[421, 504, 617, 694, 944]` -> different set when collapsed
-> **exactly the original set after expanding again**.

### Shelf renamed
`DiscoverRowLibrary` "Continue with your setup" -> **"Installed"** (user request). Reads
"Installed  40".

### Grid column headers were vertically clipped
`EnableHeadersVisualStyles = false` hands header sizing to the `DataGridView`, which sizes from
the cell font and the style's padding — the designer's auto-size height was tuned for the themed
header. Fixed in `ApplySoftGridStyle` with an explicit font-derived `ColumnHeadersHeight`.
Verified: "Installed version" renders fully.

### Grid selection was still system blue — root cause and fix
`ModList.cs` set `SelectionBackColor` on **every row's** `DefaultCellStyle`:
`SelectionBlend(c) => c == Color.Empty ? SystemColors.Highlight : ...`. A per-row style outranks
`DataGridView.RowsDefaultCellStyle`, so it silently defeated **both** `ApplySoftGridStyle`
(`SurfaceSunken`) and the `ModGrid_GotFocus` / `LostFocus` handlers (`AccentSoft`). Probed
render was exactly `(0,120,212)`.
Fix: `SelectionBlend` now returns `Color.Empty` for an untinted row so the fill inherits from the
grid (which is what makes the existing focus/unfocus accent work), and blends `SoftTheme.Accent`
over the row's own tint when it has one (label colour / conflict red). New `ApplySelection(
DataGridViewCellStyle)` helper applies both back and fore so the two call sites cannot drift.
Verified: selected row band now reads `(228,235,253)` = `AccentSoft`.
**Lesson:** a per-row `DefaultCellStyle` beats every grid-level style. If a grid-level theme
"does nothing", look for per-row/per-column style assignments first.

## Session 4 — detail pane on Apple HIG, entrance animation, tab contents

User requests: *"fix the detail pane to fit in more with the theme of the rest of the application.
Just get it to look and feel good"* then *"Use apple style guidelines make it pop in from the
sidebar feel smooth and natural"*.

### The pane is now one rounded sheet, not three stacked strips
`ModInfo.ApplySoftTheme()` was rewritten. The pane used to alternate white / grey / white down its
height, which is what made it read as three unrelated strips. Now:
- `BackColor = Backdrop` with a 14 design-unit `Padding` gutter (`ApplyGutter`, re-applied from
  `OnDpiChangedAfterParent`). The gutter is what makes the rounded corners visible: the docked
  table is inset so its square corners land inside the card, while the card's own corners show the
  backdrop through. `OnPaint` fills `ClientRectangle` with `Surface` at `RadiusCard` **before**
  `base.OnPaint` — that ordering matters, because `base.OnPaint` is what raises the `Paint` event
  the reveal draws into, so the sheet has to be underneath it.
- Title left-aligned (`MetadataModuleNameTextBox.TextAlign = Left`), and `RowStyles[0]` pinned to
  `SizeType.Absolute` sized from `Font.GetHeight()`. The name box is a **multiline TextBox docked
  into an AutoSize row**, so the row inherited the designer's fixed height for it — which at 150%
  DPI left a heading-sized hole between the title and the tags.
- `ThemedTabControl` gained a `StripColor` property (default `Backdrop` for the outer strip). The
  detail pane sets it to `Surface` so its header reads as one surface.
- `TagsLabelsLinkList` now builds a nested `TagChip : LinkLabel` — a rounded pill. It stays a
  `LinkLabel` so every existing wire-up (click to filter, middle-click to merge, context menu,
  tooltips) keeps working. `LinkLabelBottom` dropped `+ lbl.Padding.Bottom` because the padding now
  feeds the pill's own inset and the auto-sized control's preferred size.
- `Metadata` is a definition list: `AutoScroll = true` plus `MetadataTable.Paint` drawing a
  hairline under every row but the last. A re-entrancy guard (`wrapping`) was needed on
  `MetadataTable_Resize` — now that the panel scrolls, a scrollbar appearing changes the column
  widths, which is exactly the feedback loop that turns into a resize storm.

### Entrance animation — `GUI/Controls/PaneReveal.cs` (new)
Snapshot-based: `DrawToBitmap` the content, hide the real controls, repaint the snapshot with a
falling alpha, a shrinking offset and a 1.5% scale settle, then snap to the end state. Animating a
snapshot rather than the live controls is the whole point — moving real controls re-runs layout
every frame and flickers on a subtree this deep. Played from `ModInfo.SelectedModule` only when the
mod actually changes, never on a tab switch or a re-select.
Hard-won details:
- `MinAlpha = 0.3f`, **not** 0. Fading in from nothing flashes an empty pane on a white sheet,
  which reads as a glitch rather than as an entrance.
- `dx` must be **negative** so the content starts tucked under the pane's leading edge — that is
  what makes it read as arriving *from the sidebar*. Positive slides it in from the right.
- Every failure path (no handle, disposed, zero size, `DrawToBitmap` throwing) degrades to "no
  animation" rather than to a visible error.

### Versions tab — the legend labels *are* the row colours
`Versions.cs` copies each legend label's `BackColor`/`ForeColor` onto its `ListViewItem`s
(`getItems` ~L248, `checkInstallable` ~L296-307). So recolouring the four labels recolours the
table — no row logic needed. New `Versions.ApplySoftTheme()` maps:
`Color.Green` → `SuccessSoft` + `Mix(Success, TextPrimary, 0.5f)`;
`Color.LightGreen` → `SurfaceSunken` + `TextPrimary`;
`InstalledLabel` (`SystemColors.Window`) → `AccentSoft` + `AccentDeep` (legend swatch only — the
installed *row* is marked by its bold face and takes its fill from one of the other three);
`Color.Gold` → `WarningSoft` + `Mix(Warning, TextPrimary, 0.5f)`.
Probe-verified: row fills `(224,244,234)` and `(232,236,242)`, installed chip `(228,235,253)`.
**Trap:** `checkInstallable` runs on a background thread, so a capture taken right after selecting
a mod catches a half-painted table. Wait ~8 s before capturing.

### WinForms gotchas found this round
- **`TreeView.LineColor` is ignored for as long as visual styles are on** for the control. The
  dotted connectors stayed pure black `(0,0,0)` no matter what. Fix chosen: `ShowLines = false` —
  which is also the more modern reading of a tree (macOS `NSOutlineView` has no connectors), and
  the expander plus the indent carry the hierarchy on their own.
- **`ComboBox` + `DropDownStyle.DropDownList` + `FlatStyle.Flat` loses its frame and its text** and
  collapses to a bare dropdown arrow. Do not "flatten" a DropDownList combo; set colours only.
- A generic `case Button` rule in the tree-walking themer is the wrong tool: `Contents`' buttons
  were **already** `FlatStyle.Flat` from the designer (so a `!= FlatStyle.Flat` guard skipped them)
  while `Changelog`'s fetch button is a `Button` with an accent `ForeColor`/`BackColor` of its own
  (so a rule loose enough to catch the first would repaint the second). Resolved by giving each tab
  its own `ApplySoftTheme()` — `Contents.ApplySoftTheme()` styles just its two buttons — and
  dropping the Button case from the walker entirely.
- `AutoScaleMode = Dpi` on the designer **does** scale `Absolute` column widths, so the metadata
  label column was already correct at 150% DPI. Worth checking before "fixing" it.
